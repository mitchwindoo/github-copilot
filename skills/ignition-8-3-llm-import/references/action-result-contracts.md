# Action result contracts

Use this reference only with `llmImport` API v0.103.0. Discover the live version and 72-action list first. If either differs, treat this map as stale and inspect the live source contract before making a claim.

`accepted: true` means a recognized fixed action reached its normal result envelope. `passed: true` means only that the action-specific aggregate matched its fixed predicate. It does not turn observation-only fields into evidence. Require the expected `testId`, exact field shape, and exact nested values supporting the claim.

`tag-read-v1`, `tag-read-complex-v1`, `tag-browse-v1`, `tag-write-v1`, `tag-query-history-v1`, all six `alarm-*-v1` actions, `grouped-udt-file-v1`, `tag-document-cas-v1`, and the eight expression/Perspective/SFC fixture actions use `ok` instead of `passed`. For those actions, a missing `passed` field is expected; inspect their row and their per-item completeness, quality, mutation, operation, or verification fields directly.
