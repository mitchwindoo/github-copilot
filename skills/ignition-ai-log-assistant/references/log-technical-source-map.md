# Log Technical Source Map

Use this reference when a log category, logger name, source stream, or exception points to a technical area that needs source-backed interpretation. These sources explain concepts and collection locations; they do not prove root cause or replace current release/bug lookup.

## Source Map

| Log clue | Read first | Use it for | Boundary |
| --- | --- | --- | --- |
| Gateway Diagnostic Logs, Gateway-scoped errors, database/device/auth/alarm/pipeline Gateway events | Ignition 8.1 Gateway Diagnostics Logs: `https://www.docs.inductiveautomation.com/docs/8.1/platform/gateway/status/diagnostics-logs` | Understand Gateway log location, UI filters, and Gateway-side event scope. | Does not cover wrapper-only startup/JVM output. |
| Wrapper logs, service/JVM startup, stdout, print output, wrapper rotation | Wrapper Logs: `https://www.docs.inductiveautomation.com/docs/8.1/platform/gateway/status/diagnostics-logs/wrapper-logs`; Logback XML File Reference: `https://www.docs.inductiveautomation.com/docs/8.1/appendix/reference-pages/logback-xml-file-reference` | Locate wrapper files and interpret wrapper-vs-embedded Ignition log structure. | Paths and rotation settings are install-specific. |
| Script logger names, `system.util.getLogger`, Gateway/client script output, `print` output | Script Logging and Print Statement Output: `https://www.docs.inductiveautomation.com/docs/8.1/platform/scripting/scripting-in-ignition/script-logging-print-statement-output`; `system.util.getLogger`: `https://www.docs.inductiveautomation.com/docs/8.1/appendix/scripting-functions/system-util/system-util-getLogger` | Decide which console/log stream should contain a script message. | Do not change logger levels without authorization. |

## Operating Pattern

1. Route from the evidence category and source stream first, then logger/message text.
2. Use the linked source to understand where evidence should appear and what fields matter.
3. Return to source-labeled logs for root-cause claims.
4. Use current release/vendor lookup separately for version-specific bug, fix, compatibility, or latest-version claims.
