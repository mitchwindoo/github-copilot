<technical_details>
- Environment/stack:
  - Windows WPF app targeting net10.0-windows.
  - xUnit + FlaUI UI automation tests.
  - Frequent file lock contention on Release binaries during parallel build/test or when app remained open.

- Key decisions:
  - User-directed rollback: hard-lock to light-only theme and remove appearance-selection controls.
  - Navigation evolution:
    1) custom workspace button rail,
    2) tab-like buttons,
    3) true tab control with Actions/History/Config,
    4) inline History content replacing popup-launch button.
  - Dependency Center kept popup-only per user direction while Config tab hosts config-facing controls.

- Issues encountered and resolutions:
  - WPF/XAML parse errors from mismatched tags during large tab-content refactors; resolved by structural rebalancing and targeted file-range checks.
  - UI test breakages after UX moves:
    - selectors depended on moved controls (Add button, History button).
    - fixed by updating automation paths/ids and tab-selection flows.
  - Branch-list automation assertion failed when item names surfaced as type names; fixed by setting ListBoxItem automation name bindings.
  - Build/test intermittent locking (apphost/dll/wpftmp) caused MSB3021/MSB3027/CS2012; resolved via process termination and sequential validation.

- Non-obvious behaviors:
  - Running build and tests in parallel in this environment frequently races on WPF intermediate/output files.
  - UI tests can leave app process alive after failures, requiring manual process cleanup.
  - Screenshot assets under docs are touched whenever wiki screenshot tests run; they appear as modified even for logic-focused edits.

- Open uncertainty:
  - Inline History tab now uses plain text output rendering for log area rather than the previous RichText severity-color pipeline from popup code-behind; called out as a remaining risk/possible polish follow-up.
</technical_details>
